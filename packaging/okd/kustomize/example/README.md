# Example overlay — not an install target

`api/` illustrates a normal Kustomize JSON6902 site patch over the checked-in
product base. It deliberately retains `registry.invalid` images, fake digests,
example hosts and storage classes. **Do not apply it or any bare base stage.**

For an actual installation, fill a private copy of
[`../../config.example.json`](../../config.example.json) with the site's
explicit `resource_prefix` (`vesta` for new examples), namespaces, hostnames,
image digests, storage classes, Secret names and resource
budgets. The renderer validates those inputs and writes a complete, portable
overlay for one stage at a time:

```bash
python3 packaging/okd/render.py --config /private/site.json \
  --stage api --output-dir /private/release/api
oc kustomize /private/release/api > /private/release/api.reviewed.yaml
```

The generated target includes a copy of its version-matched base and only
site-varying patches. It refuses an existing output directory and a stale
checked-in base. Generate `migrate`, `restore-grants` and `agent` separately;
never apply fresh migration and restored grants together. Add any local patches
to the generated target and review its final `oc kustomize` output before
applying. Secret values are never generated by this renderer.

Keep the installed site's original `resource_prefix`, including an omitted value. This fresh illustrative patch targets `vesta-backend`;
it is not an instruction to rename a legacy Deployment. Use the actual accepted
site file for upgrades and the matching generated base/site overlay.
